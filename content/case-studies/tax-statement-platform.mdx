## Context

At quarter end an accounting firm prepares sales-tax and payroll statements for every client business. The data sits in a cloud accounting platform, but the work was manual: export reports, reconcile, check, build a workbook, write notes for the partner. The aim was a product other firms could subscribe to.

## What I built

A multi-tenant SaaS with a web app, an API and background workers on a managed container platform. A firm connects each client organisation. Statement runs then go through a pipeline of about 13 steps: fetch, reconcile, apply fallbacks, calculate, cross-check, validate, comment, and build a formula-driven workbook that a reviewer can trace and sign off.

The platform includes:
- self-service sign-up and subscription billing
- team roles
- an audit log
- tenant isolation checked automatically in CI
- runbooks and a public status page

## Key decisions

- **The AI writes commentary only.** Every number comes from exact decimal arithmetic and rule-based validation. One read-only model call writes three or four sentences for the partner. It takes no actions, and falls back to "commentary unavailable" if anything goes wrong.
- **Independent cross-source checks.** About 20 rules compare the provider's reports, the transaction ledger and payroll. Each returns pass, inform, warn or fail, and a divergence between two sources can block a run.
- **Data-driven classification.** Hard-coded heuristics were replaced with classification driven by the provider's own metadata, and fallbacks fail loudly. The redesign was planned to shrink that code by about three-quarters.
- **AI-assisted engineering under control.** Coding agents worked behind written invariants, feature flags and test gates. A second model reviewed validator output against ground truth.

## How quality was measured

A verification protocol for every calculation:
1. probe the real API
2. freeze a fixture
3. write the test
4. write the code
5. check against the provider's own figures
6. repeat on a second organisation

Validator reports compared statement lines to ground truth for pilot clients.

## Results

- About 1,100 automated tests across the platform.
- Key statement fields matched the provider's own figures exactly for pilot clients [confirm].
- The code side of the accounting platform's marketplace certification was complete (9 of 9 checkpoints) [confirm].

## What I would do next

Finish the marketplace listing, and add model-suggested coding for unclassified transactions. Each suggestion would be shown to the reviewer and never applied automatically.

The public repository rebuilds the core pattern on a fictional tax regime: deterministic figures, a blocking validation gate, one grounded AI call, replay from stored inputs, and a fault-injection test of the provider client.
